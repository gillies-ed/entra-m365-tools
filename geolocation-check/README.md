# Geo Location Report Viewer

A PowerShell + browser tool for analysing Microsoft Entra ID (Azure AD) sign-in logs by geography. Load a sign-in CSV export, visualise where users are signing in from, detect impossible travel, and generate plain-English summaries for line managers.

![Screenshot of the Geo Location Report Viewer showing a user timeline with country flags and sign-in events]

## Features

- **Per-user timeline** — sign-in events grouped by day, colour-coded by country
- **Country & OS filters** — click to filter any user's timeline
- **Summary table** — all users × all countries in a single grid, click any cell to drill in
- **Manager Report** — list flagged users alongside their line manager (requires Graph API)
- **Impossible travel detection** — flags physically impossible consecutive sign-ins using great-circle distance and realistic travel speeds
- **LLM narratives** — generates plain-English summaries per flagged user via a local LLM (optional)
- **Drag and drop** CSV loading

## Requirements

- **PowerShell 7+** (`pwsh`) — works on Windows, macOS, Linux
- **Microsoft.Graph module** (only needed for Get Line Managers):
  ```powershell
  Install-Module Microsoft.Graph -Scope CurrentUser
  ```

## Quick Start

```powershell
cd v2
.\Start-GeoLocationViewer.ps1
```

Opens `http://localhost:8765` in your browser. Drag and drop a sign-in CSV to load it. No credentials required for offline use.

## Get Line Managers

To resolve line managers via Microsoft Graph, register an Entra app with delegated `User.Read.All` permission, then pass the IDs at startup:

```powershell
.\Start-GeoLocationViewer.ps1 -ClientId 'your-app-client-id' -TenantId 'your-tenant-id'
```

The browser will prompt for interactive sign-in the first time you click **Get Line Managers**.

### App registration steps

1. Go to [Entra admin centre](https://entra.microsoft.com) → App registrations → New registration
2. Name it something like `geo-location-report`, set redirect URI to `http://localhost`
3. Under API permissions → Add → Microsoft Graph → Delegated → `User.Read.All` → Grant admin consent

## LLM Narratives (optional)

Narratives are generated by calling an OpenAI-compatible local LLM. The default endpoint is `http://localhost:11434/v1` (Ollama).

```powershell
.\Start-GeoLocationViewer.ps1 -LlmEndpoint 'http://localhost:11434/v1'
```

Any model that follows the `/v1/chat/completions` API works. Leave `-LlmEndpoint` empty to disable the feature.

## Input Format

Standard Entra sign-in log CSV. Export from the [Entra admin centre](https://entra.microsoft.com) → Users → Sign-in logs → Download CSV.

Required columns:

| Column | Description |
|--------|-------------|
| `TimeGenerated` | ISO 8601 timestamp |
| `UserPrincipalName` | UPN (e.g. `user@<enter_your_domain_here>.com`) |
| `UserDisplayName` | Display name |
| `LocationDetails_countryOrRegion` | Country name or ISO code |
| `LocationDetails_city` | City |
| `LocationDetails_state` | State / region |
| `AppDisplayName` | App signed into |
| `DeviceDetail_operatingSystem` | OS |
| `ClientAppUsed` | Client type |
| `DeviceDetail_browser` | Browser |
| `IPAddress` | Source IP |
| `IsInteractive` | `True` / `False` |

## Test Data

`test-data/geo-location-weekly-report.csv` contains sample data for 17 fictional users with a mix of UK and international sign-ins, including an impossible travel scenario.

`test-data/Set-ManagerRelationships.ps1` — example script for wiring up an org structure in a dev tenant. Edit it for your own tenant before running.

Both files use `<enter_your_domain_here>` as a placeholder tenant domain. Replace it with your actual `.onmicrosoft.com` tenant name before use — for example, on Linux/macOS:

```bash
sed -i 's/<enter_your_domain_here>/mytenant/g' \
  test-data/geo-location-weekly-report.csv \
  test-data/Set-ManagerRelationships.ps1
```

Or in PowerShell:

```powershell
Get-ChildItem test-data | ForEach-Object {
    (Get-Content $_.FullName) -replace '<enter_your_domain_here>', 'mytenant' |
    Set-Content $_.FullName
}
```

## Impossible Travel Detection

For each user's events sorted chronologically, consecutive sign-ins from different countries are tested:

1. Both countries are looked up in an approximate centroid table (~60 countries)
2. Great-circle distance is calculated using the haversine formula
3. Minimum travel time is computed as `distance_km / 900 + 2h` (cruising speed + airport overhead)
4. If the actual gap is less than the minimum, the event pair is flagged

The centroids are geographic centres, not airports — distances are conservative estimates. Reliable for intercontinental cases; may have false positives for large adjacent countries.
